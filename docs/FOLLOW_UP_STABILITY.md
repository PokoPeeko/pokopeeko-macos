# 후속 안정성·예외 처리

음악 연동과 앱 사용 시간 공유의 정상 흐름을 먼저 구현하고, 아래 항목은 후속 안정성 작업으로 관리한다. 성능 최적화와는 구분한다. 아직 결정되지 않은 정책이나 API 필드명을 확정한 문서는 아니다.

## 현재 핵심 범위

- 정상 앱 포커스 전환 시 이전 앱 측정을 정지하고 새 앱 측정을 시작·재개한다.
- 같은 실행 ID에서는 포커스 복귀 후 누적을 이어가고, 정상 앱 종료 후 재실행은 새 기록으로 시작한다.
- 서버 기준 누적 시간과 마지막 포커스 시각으로 표시한다. 최초 접속 때도 서버의 현재 상태를 받아 표시한다.
- Mac 음악 앱에서 곡·가수·재생 상태를 읽어 공유한다. 일시정지는 PAUSE로 전달하고 종료는 음악 삭제 이벤트로 연결했다. 음악 삭제 알림에 timestamp가 없어 삭제와 이전 비동기 조회가 경합하는 경우의 순서 보장은 후속 검토한다.
- 기존 Socket.IO 연결·인증과 상태 이벤트 구조를 재사용하고, 추가 필드는 백엔드와 확인한다.

## 후속 항목

| 항목 | 후속 검토 내용 |
| --- | --- |
| 강제 종료·네트워크 단절 | 종료 이벤트 없이 끊겼을 때 마지막 생존 확인 시각 기준 마감, 무한 시간 증가 방지 |
| PokoPeeko 재실행·재연결 | 계속 실행 중인 대상 앱의 실행 ID 매핑 복원, 종료 누락 식별, 서버 상태 재동기화 |
| 이벤트 중복·순서 변경 | 송신 순번·중복 식별·적용 확인·서버 상태 버전 정책 |
| 여러 Mac 동시 사용 | 사용자별 측정 대상 기기 선정 및 중복 집계 방지 |
| 잠금·잠자기·유휴 | 포커스 변경 없이 활동이 멈추는 경우의 중지·재개와 유휴 판단 기준 |
| 차단·비공개 | 기존 차단·노출 의미를 유지하면서 측정 제외와 친구 공개 범위를 구분 |
| 상태 만료·기록 보관 | 60초 TTL의 실시간 상태와 누적 기록 수명 분리, 만료 후 복원·보관 기간 검토 |
| 시계 차이·지연 | 서버 기준 시각 동기화와 화면 표시 보정 |

기본 구현 완료와 위 예외 상황 검증 완료를 구분해 보고한다. 이미 있는 세션 보호·차단·비공개 처리와 재연결 처리를 제거하는 범위는 아니다.
