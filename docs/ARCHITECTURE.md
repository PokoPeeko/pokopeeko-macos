# PokoPeeko — Architecture

## 1. 시스템 구성

PokoPeeko는 macOS 클라이언트와 백엔드 서버로 구성된다.

- macOS 클라이언트: 앱 활동 감지, 서버 통신, 친구 활동 상태 및 사용 시간 표시
- 백엔드 서버: 사용자 및 활동 상태 관리, 누적 사용 시간 관리, 실시간 이벤트 전달
- Firebase Authentication: Apple 로그인 인증 처리

일반적인 데이터 요청에는 REST API를, 실시간 활동 공유에는 WebSocket을 사용한다.

## 2. 클라이언트 아키텍처

MVVM과 Feature-based 구조를 사용한다.

주요 기능은 다음과 같이 구분한다.

- Auth: 로그인 및 인증
- Main: 메인 앱 내비게이션
- MenuBar: 메뉴바 팝오버 UI
- Presence: 실시간 활동 상태 및 동기화
- Dashboard / Friends / Apps / Profile / Settings / Info / Feedback: 메인 앱의 개별 기능

기능별 내부 구조는 구현에 따라 조정할 수 있다.

### 2.1 현재 UI 구성

- `MainView`는 `NavigationSplitView`로 화면을 전환한다.
- `MainViewModel`은 현재 선택 화면과 UI 확인용 샘플 데이터를 보유하며 메인 앱과 팝오버에서 같은 인스턴스를 사용한다. 샘플은 정적 표시 데이터이며 서버 상태를 나타내지 않는다.
- 메뉴바 팝오버는 기존 `FriendStatus` 기능 폴더를 사용한다. 목록과 행을 메인 앱의 친구 화면에서도 재사용한다.
- `Shared/Components`에는 공통 카드·앱 심볼 등을, `Shared/Models`에는 공통 표시 모델과 시간 포맷을 둔다.
- 인증 진입과 세션 상태는 기존 경로를 유지하고, Debug 전용 별도 창에서 인증과 독립적으로 UI를 확인한다.
- 테마 선택은 `AppStorage`로 저장한다. 서버 통신이나 활동 추적은 아직 UI 데이터에 연결되지 않았다.

## 3. 앱 활동 추적

### 3.1 이벤트 감지 및 전송

1. 클라이언트가 macOS 앱의 포커스 변경 및 종료 이벤트를 감지한다.
2. 이벤트에 앱 식별자와 발생 시각을 포함하여 서버에 전달한다.
3. 서버가 이벤트를 처리하여 활동 상태와 누적 사용 시간을 갱신한다.
4. 서버가 변경된 상태를 친구들의 클라이언트에 전달한다.

### 3.2 사용 시간 관리

- 서버는 앱별 누적 사용 시간과 현재 활성 앱의 시작 시각을 관리한다.
- 클라이언트는 서버에서 전달받은 정보를 기준으로 표시 시간을 계산한다.
- 앱 전환 시 기존 앱의 누적 시간을 확정하고 새로운 활성 앱의 측정을 시작한다.
- 이전 앱이 다시 활성화되면 기존 누적 시간부터 이어서 측정한다.
- 서버와 클라이언트는 각각 시간 차이를 계산하지만, 클라이언트가 계산한 누적 시간을 서버에 매번 전송하지 않는다.

## 4. 실시간 상태 동기화

### 4.1 초기 연결

1. 클라이언트가 WebSocket에 연결한다.
2. 서버가 현재 활동 상태와 누적 사용 시간을 전달한다.
3. 클라이언트가 초기 상태를 반영한다.
4. 이후 변경 이벤트를 실시간으로 수신하여 상태를 갱신한다.

### 4.2 재연결

- 연결 복구 시 서버의 최신 상태를 다시 동기화한다.
- 연결이 끊긴 동안 발생한 모든 이벤트를 재생하는 대신 서버에 저장된 현재 상태와 누적 시간을 사용한다.
- 초기 상태와 실시간 이벤트의 적용 순서가 충돌하지 않도록 처리한다.

## 5. 인증 및 세션

- Apple 인증 결과를 Firebase Authentication에 전달한다.
- Firebase ID Token을 백엔드에 전달하여 사용자를 인증한다.
- 백엔드가 발급한 세션은 macOS Keychain에 저장한다.
- 신규 사용자 여부는 백엔드 응답을 기준으로 판단한다.
- 신규 사용자는 별도 프로필 설정 과정을 거친다.

## 6. 미확정 사항

다음 항목은 관련 기능 구현 전에 설계한다.

- WebSocket 메시지 및 이벤트 데이터 구조
- 이벤트 순서 보장 및 중복 처리
- 서버와 클라이언트의 시간 차이 처리
- 네트워크 연결 끊김 및 재연결 정책
- 앱 종료 이벤트 누락 시 처리
- 활동 데이터 저장 범위 및 보존 기간

확정된 설계는 구현과 함께 문서에 반영한다.
